## Multibody Dynamics and Geometry

<!-- <relnotes for geometry,multibody go here> -->

* [feature] TBD Introduce concept of "inactive" proximity geometry in collision filters ([#24614][_#24614])  # Marking a geometry as inactive has the effect of declaring it permanently filtered. An inactive geometry will not appear in any collision candidate pair. (It is still a valid geometry for distance-to-point queries). This is intended as a big hammer to help performance. Used in conjunction with locking/sleeping, marking a geometry as "inactive" will remove it from *all* query algorithms (including broadphase). Typical collision filters only cull filtered geometry pairs *after* the broadphase has completed. The activity status removes it from the broadphase as well. It's a more expensive switch to flip, but it leads to cheaper query results.
* [feature] TBD [geometry,examples] Meshcat visualizer supports deformables ([#24608][_#24608])
* [fix] TBD Fix bug in scalar converting MultibodyPlant vis a vis DeformableModel ([#24640][_#24640])  # DeformableModel reports that it is only cloneable to AutoDiffXd or Symbolic if it is _empty_. However, attempting to clone the plant would nevertheless "succeed". The cloned result would have the registered deformable models stripped out of the DeformableModel. Rather than silently creating a lossy clone, this changes the behavior to throw. It provides mechanisms to enforce that and provides details on why the plant can't be scalar converted. Specifically, MultibodyPlant needed its invocation of RemoveUnsupportedScalars() removed from the scalar-converting constructor to FinalizePlantOnly() to close a gap in conversion logic. - The scalar copy constructor can only be called on finalized plants (a documented requirement). - However, the finalized plant hadn't necessarily recognized which conversions were valid yet. - So, the conversion would happena and the converted *copy* would know if it was convertible; but the source may have been wrong. This subverted the system conversion mechanism. By making sure a finalized plant knows what target scalar types are valid, the conversion constructor automatically benefits. This is *in theory* a breaking change because it changes observable behavior. If a user was cloning a plant with deformable bodies into an unsupported scalar type, but ignored the fact that the deformable bodies were gone, this constitutes a new exception.

* [fix] TBD [multibody] CENIC constraints handle small time steps ([#24661][_#24661])
* [fix] TBD [parsing] Elide identity frames in joint parsing ([#24687][_#24687])

# Notes


This release provides
[pre-compiled binaries](https://github.com/RobotLocomotion/drake/releases/tag/v1.55.0).
See [Installation](/installation.html) for instructions on how to use them.

Drake binary releases incorporate a pre-compiled version of
[SNOPT](https://ccom.ucsd.edu/~optimizers/solvers/snopt/) as part of the
[Mathematical Program toolbox](/group__solvers.html). Thanks to
Philip E. Gill and Elizabeth Wong for their kind support.
