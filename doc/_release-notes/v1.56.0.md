## Multibody Dynamics and Geometry

<!-- <relnotes for geometry,multibody go here> -->

* [feature] TBD [parsing] Support sap distance constraints ([#24737][_#24737])  # Assisted-By: GPT-5.6 Sol <noreply@openai.com>
* [fix] TBD Disable distance constraint in IK if stiffness is finite ([#24752][_#24752])  # When the stiffness in the distance constraint is infinite, then it means the distance constraint is hard, and we will impose the distance constraint in inverse kinematics; otherwise we ignore the distance constraint in IK.
* [fix] TBD [multibody] AddMultibodyPlantConstraints rejects null plant_context ([#24756][_#24756])  # When the plant contains distance constraints, the plant_context was documented to be a required parameter, but this was not enforced. Our contract says that we must throw in this case.
* [fix] TBD [geometry] Remove RenderEngine::SetDefaultLightPosition ([#24762][_#24762])  # This function was documented as internal use only and has no callers.
* [feature] TBD [CENIC] Support ball constraints ([#24730][_#24730])  # Adds support for ball constraints in IcfSolver and thus CENIC.
* [fix] TBD Upgrade RenderEngineGl's image readback ([#24726][_#24726])  # Using glReadPixels is much faster than glTextTextureImage (the latter incurs a number of pieces of overhead that are unnecessary when all we want to do is read back from an uncompressed frame buffer).
* [feature] TBD [multibody] Adds python bindings for MultibodyPlant::AddTendonConstraint() ([#22813][_#22813])
* [feature] TBD [CENIC] Support distance constraints ([#24776][_#24776])  # Adds support for distance constraints in IcfSolver and thus CENIC.
* [feature] TBD Optionally relax constraints in TOPPRA to handle numerically-challenging trajectories ([#24798][_#24798])
* [fix] TBD [geometry,systems] [render] Correct RenderEngineGL "upside down" images ([#24823][_#24823])  # If a camera using RenderEngineGl sets its `show_window` to true, the image would be displayed upside down. This changes the "blitting" of the rendered image to cause the interactive window to display the right side up. As the beginning of a number of changes to RenderEngineGl, this also makes the engine available to easy introspection via model_visualizer. The render engine can be selected as a command-line parameter. This changes the --show_rgbd_sensor parameter. It is no longer a bool-valued argument. Now it is string-valued. The old usage will now raise errors.
* [feature] TBD [multibody,geometry] Add a LeafSystem for dragging objects from meshcat ([#24673][_#24673])  # Author: Vince Kurtz <vjkurtz@gmail.com> Assisted-By: Claude Opus 4.8 <noreply@anthropic.com>
* [feature] TBD [render] Update label images ([#24838][_#24838])  # The update comprises multiple parts: 1. For both RenderEngineGl and RenderEngineVtk, when asking to display the label interactively, the *displayed* image is colorized (the returned image is unchanged). 2. RenderEngineGl is made far more efficient (the label image is rendered directly on the GPU, reducing CPU-side computation). RenderEngineVtk still does this extra work. 3. model_visualizer is given the ability to choose label as the type of image to show from the sensor. Note: defining automated tests on the output of an interactive window is cumbersome at best. For this functionality, we're relying on human evaluation via model_visualizer. It won't catch potential regressions, but we accept the risk.

## Newly-deprecated APIs

<!-- <relnotes for newly-deprecated go here> -->

* [newly deprecated] TBD [tools,workspace] [workspace] Deprecate the zlib_repo flag ([#24814][_#24814])  # The zlib_repo flag is deprecated for removal; the future default will be "source". If you want to build zlib from source as a Bazel module, no action is necessary (that will be the future default). If you want to keep using "hardcoded", you must either use --override_module on the command line or local_path_override in MODULE.bazel. This is a necessary prerequisite to depending on modules from BCR that use zlib. It is impractical to redirect their dependency on zlib to use Drake's selection instead. Withdraw the TODOs about deprecating the zlib and libjpeg module extensions. For downstream Bazel users, it's important to allow linking against the libraries built with our transitioned build flags so that users don't end up with two copies. Update our docs to reflect this.

# Notes


This release provides
[pre-compiled binaries](https://github.com/RobotLocomotion/drake/releases/tag/v1.56.0).
See [Installation](/installation.html) for instructions on how to use them.

Drake binary releases incorporate a pre-compiled version of
[SNOPT](https://ccom.ucsd.edu/~optimizers/solvers/snopt/) as part of the
[Mathematical Program toolbox](/group__solvers.html). Thanks to
Philip E. Gill and Elizabeth Wong for their kind support.
