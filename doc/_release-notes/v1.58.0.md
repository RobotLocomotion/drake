# Announcements

<!-- <relnotes for announcements go here> -->

* [fix announce] TBD [common,solvers,math,examples,planning] Prefer dedicated mathematical comparators over specializations ([#25014][_#25014])  # Newer libc++ introduced a map and set lookup optimization that requires `std::less` specializations to be equivalent to `operator<`. Any other behavior is non-conforming. For more context on the change, see the discussion on the below LLVM issues [1,2]. SolverId and Formula simply need operator overloads. For Expression and Variable, their `operator<`s are used for logical comparison while their `std::less` specializations are used for structural comparison. (Ditto for `std::equal_to` vs. `operator==`.) Instead, we provide new comparators, and port Drake's containers to use them throughout. The old specializations are deprecated, but for compatibility during the deprecation period, the new comparators are still an alias to the old on platforms where they aren't strictly required (i.e., older libc++, or libstdc++). [1] https://github.com/llvm/llvm-project/issues/178847 [2] https://github.com/llvm/llvm-project/issues/179319

* [fix] TBD [solvers,workspace] [workspace] Update dependency scs_internal to 3.3.1 ([#25047][_#25047])
* [fix] TBD [solvers] Solve QPs with CLP's barrier method ([#25020][_#25020])  # Previous, CLP would fail on certain trivally-feasible QPs. Switching to the barrier method enables it to solve these programs correctly. This commit also adds CLP back to the list of QP-capable solvers. Resolves #22985.
* [fix] TBD [solvers] Avoid CLP crossover UB on QPs with no linear constraints ([#25055][_#25055])  # Since #25020, ClpSolver solves QPs with barrier plus crossover. When the model has no rows, CLP's primal pricing computes sizeFactorization_ / numberRows = 0.0 / 0.0 and casts the NaN to int, which UBSan flags. Give such models an empty free row so crossover still runs and the solution and duals remain exact. Skipping crossover instead would lose the exact bound-constraint duals, and skipping it only for fully unconstrained programs still hits the UB when some variables are bounded and others are free; the new regression test covers that case.
* [fix] TBD Ensure NLopt Returns Success = False for NaN Solutions ([#25053][_#25053])  # If the returned solution contains NaN, report kSolverSpecificError. NLopt does not guard against NaN values from the user's functions: with NaN gradients (e.g., from some signed distance queries), algorithms such as LD_AUGLAG_EQ step to x = NaN and keep going, and can then terminate with a success-like status.

## Multibody Dynamics and Geometry

<!-- <relnotes for geometry,multibody go here> -->

* [fix] TBD [render_gl] Remove light limit (and streamline shaders) ([#24953][_#24953])  # The primary benefit is the removal of the hard-coded light limit. Attendant with that, we streamlined the shaders. - We no longer encode an "empty light" slot. The shader knows exactly how many lights it has. - The transformation of geometry vertices from the "model" frame to the device clip space used to use two matrices (provided as uniforms). The decomposition wasn't really helpful as we multipled the matrix for every vertex in the geometry. Instead, we now pre-compute on the CPU and pass it once per object.
* [fix] TBD [parsing] Report nested URDF world-weld prefix errors via DiagnosticPolicy ([#24965][_#24965])
* [feature] TBD [parsing] Use DiagnosticPolicy for model directives errors ([#24938][_#24938])  # Wire model directives loading and parsing to DiagnosticPolicy so errors follow the same non-fatal policy path as URDF and SDFormat. IsValid() schema checks report via the policy, and parser throws are replaced with diagnostic.Error() plus continue/return.
* [fix] TBD [multibody] Throw if CalcSpatialInertia frame is not in the plant ([#24934][_#24934])  # Validate that frame_F belongs to this MultibodyTree before computing spatial inertia, so an unowned FixedOffsetFrame throws instead of segfaulting. Also regenerate MultibodyPlant docstrings and update tests that exercised unowned frames (fused welds, momentum/energy). Fixes #22636.

## Planning

<!-- <relnotes for planning go here> -->

* [fix] TBD Fix SceneGraphCollisionChecker Signed Distance Gradient Sign Flip with Padding ([#25017][_#25017])  # SceneGraphCollisionChecker's RobotClearance jacobian has the wrong sign whenever the collision padding moves the signed distance across zero: a pair that is separated but closer together than a positive padding, or a pair that is penetrating by less than the magnitude of a negative padding. See #25016. This test slides a robot sphere on a prismatic joint toward a welded environment sphere. The gradient of the distance with respect to the joint position is -1 in every posture and for every padding, so the test pins that value across both zero-crossing cases and five control cases where the padding leaves the sign of the distance alone. DoCalcContextRobotClearance chose the sign of the spatial distance gradient from the padded distance, but the witness points it normalizes come from the unpadded signed distance query. SignedDistancePair guarantees (p_WCa - p_WCb) = distance * nhat_BA_W for the unpadded distance, so whenever padding moved the reported distance across zero the gradient came back negated: a positive padding larger than the gap between two separated geometries, or a negative padding larger in magnitude than the depth of a shallow penetration. The reported distances themselves were always correct; only the jacobian was affected, and only for pairs in that regime. Key off the unpadded distance instead. This resolves #25016 and makes the regression test added in the previous commit pass.

# Notes


This release provides
[pre-compiled binaries](https://github.com/RobotLocomotion/drake/releases/tag/v1.58.0).
See [Installation](/installation.html) for instructions on how to use them.

Drake binary releases incorporate a pre-compiled version of
[SNOPT](https://ccom.ucsd.edu/~optimizers/solvers/snopt/) as part of the
[Mathematical Program toolbox](/group__solvers.html). Thanks to
Philip E. Gill and Elizabeth Wong for their kind support.
