# Breaking changes since v1.58.0

<!-- <relnotes for breaking-changes go here> -->

* [breaking change fix] TBD [solvers] Report NLopt status and point on every return code ([#25079][_#25079])  # NloptSolver turned NLopt's negative return codes into exceptions and then dropped both the code and the point NLopt had written, leaving status 0 and an all-NaN solution. It now disables NLopt's C++ exceptions, records the return code on every termination, and keeps NLopt's point on every code except INVALID_ARGS and OUT_OF_MEMORY. The SolutionResult mapping is unchanged. Exceptions thrown by costs and constraints, previously swallowed by NLopt's C++ wrapper, are now rethrown from Solve() with their message, matching SnoptSolver.
* [breaking change newly deprecated feature] TBD [planning] Add ComputeConfigurationDeltas to DistanceAndInterpolationProvider API ([#25115][_#25115])  # Feature: adds ComputeConfigurationDeltas method to DistanceAndInterpolationProvider API. Breaking change: implementations of DistanceAndInterpolationProvider must implement the new method DoComputeConfigurationDeltas; no default implementation is provided. See //planning/linear_distance_and_interpolation_provider.cc for an example implementation of the new method. Newly deprecated: constructing and using a CollisionChecker implementation with the legacy distance and interpolation functions is now deprecated and support for this will be removed on or after 2027-02-01. A DistanceAndInterpolationProvider must be used instead.
* [breaking change] TBD [multibody,common] MultibodyPlantConfig.use_sample_output_ports allows 'Unchanged' ([#25218][_#25218])  # The setting is no longer ignored for a continuous-time plant. Instead, the 'Unchanged' option (the new default) can be used to indicate that the plant setting should be left alone. Users with a config file that sets both `time_step: 0` and `use_sampled_output_ports: true` should change the `true` to either `false` or `!Unchanged {}`.
* [breaking change fix] TBD [tools,doc,solvers] [wheel] Don't require Mosek by default ([#25220][_#25220])  # When installing Drake via pip, users must now opt-in to the `[mosek]` extra to request installing Drake with MOSEK support. This results in a smaller install footprint (on Linux) for users who don't have a MOSEK license, or don't need to use it. On macOS we allow using the extra for forward compatibility, but at the moment we still install Mosek even when not opted in because lazy loading of the MOSEK dylib is still a work in progress. Users who need MOSEK should still specify the extra now, so that in the future when we switch to opt-in no futher changes will be necessary.
* None

## Multibody Dynamics and Geometry

<!-- <relnotes for geometry,multibody go here> -->

* [fix] TBD [parsing] Preserve poses of SDF frames attached to joints or later frames ([#25095][_#25095])  # When an attached_to target is a joint or a frame declared later, the parser now attaches the new frame to the target’s resolved body or implicit model frame (previously would use an incorrect default). Adds regression coverage for later-declared frames, static-model frame offsets, and joint attachments whose child belongs to a nested model.
* [fix] TBD Make SetVelocitiesInArray preconditions check consistent with similar methods ([#25110][_#25110])
* [fix] TBD [multibody] Apply q's gradient once in MultibodyPlant-based Distances ([#25107][_#25107])  # When MinimumDistanceLowerBoundConstraint or MinimumDistanceUpperBoundConstraint is constructed from a MultibodyPlant<double> and evaluated in AutoDiffXd, Distances() called math::ExtractGradient(q) once per geometry pair in range, rebuilding the same positions-by-derivatives matrix every time. It now stacks ∂distance/∂q for all pairs and applies q's gradient with one matrix product, as the CollisionChecker-based Distances() already does. The ∂distance/∂q computation is shared with CalcDistanceDerivatives(), which DistanceConstraint still uses. Adds a test with several pairs in range, a non-identity gradient of q, and q without derivatives.
* [fix] TBD [parsing] Put each SDFormat frame in the model instance that declares it ([#25123][_#25123])  # Drake gave an explicit SDFormat <frame> the model instance of whatever it is attached to, rather than that of the model that declares it. Usually those are the same, but not when a frame is attached to something in another model: for example, a frame in an outer model attached to a link in a nested model, or a world-scope frame attached to a model. Such a frame then: - could not be found by its name in the model that declares it, so, for example, a <drake:joint> could not name it in <drake:parent> or <drake:child>; and - collided with any frame of the same name in the model it was attached to, so that a valid SDFormat file failed to parse with "Model instance 'outer::inner' already contains a frame named 'F'". Now every explicit frame belongs to the model instance of the model (or the world) that declares it, consistent with SDFormat's name scoping. The link it is fixed to, and its pose there, are unchanged. This does change the model instance of such cross-model frames in existing models. Code that found one through the model instance of its attachment, or by a scoped name through that model, must now use the declaring model instead; a lookup by unscoped name alone is unaffected. Among Drake's own .sdf files, only three parser test models have such frames, and their tests look the frames up by name alone.
* [fix] TBD [multibody] Fix undefined behavior in CalcJacobianSpatialVelocity with no degrees of freedom ([#25131][_#25131])  # Under UBSan the test fails: with zero columns the Jacobian matrices have a null data pointer, and bottomRows<3>() offsets it (drake#17113). The fix is to return early when the Jacobian has no columns, before forming row blocks of zero-column matrices.
* [feature] TBD [multibody] Add MultibodyPlant::CalcHessianSpatialVelocity ([#25111][_#25111])  # Computes the derivatives of J𝑠_V_ABp_E along each 𝑠 = eᵢ in closed form, visiting only the mobilities on the paths of A, B and E, at under twice the cost of the Jacobian (autodiff costs 40-60x). Adds Mobilizer::CalcHMatrixPartials (∂H_FM/∂q) as the only mobilizer-specific ingredient. With 𝑠 = q̇, joints with q̇ ≠ v between A and B are not yet supported. Also binds it in pydrake, as one (n, 6, n) array, and adds Hessian cases to the Cassie benchmark.
* [fix] TBD [parsing] Fix and extend frame references in SDFormat drake: tags ([#25132][_#25132])  # This changes how <drake:parent>, <drake:child>, <drake:bushing_frameA>, and <drake:bushing_frameC> look up the frames they name, and how a <frame>'s attached_to resolves a model's name. It was split out of #25125 (drake:independent_frames), which builds on it, to keep that PR reviewable. Frame names in those tags now go through a new FindFrame(), which replaces the lookup in ParseFrame(): - They may name `world` and models (meaning a model's implicit frame), as well as links and frames. Both used to be errors. Extra scope delimiters are ignored, as they already were for other names. - They must not name an SDFormat joint. That was already an error unless the name matched a frame Drake generated for another joint (such as foo_child for a joint foo), in which case it silently resolved to that unrelated frame, on a different link. Joints from included URDF and MJCF files count too; their scoped names are recorded while libsdformat loads the file. - They resolve only to model instances that parsing the same source added (FindSourceModelInstance()). The plant may hold model instances with the same scoped name from earlier parses, for example with a model name prefix; before, a scoped name such as foo::L could silently resolve into one of those. A <frame> whose attached_to names a model gets the same rule; that bug predates this PR. - They must not name a model's implicit frame, by the model's name or as __model__, if Drake fixed that frame to the world. It does so when the model's canonical link is deformable or comes from an included URDF or MJCF model (#25129), or when the model has no links. Named as __model__, such a frame used to be returned silently. - Empty and ::-only names were already errors; the message is clearer now. - Diagnostics name the referring <drake:joint>. Related problems that predate this PR are tracked in #25128 (prefixes and auto-renaming with URDF/MJCF includes and world-scope references), #25129 (the world-fixed implicit frame itself), and #25130 (a crash in the URDF/MJCF include callback). Tests cover each rule for <drake:joint> and bushing references: model and nested-model scopes, URDF includes (merged or not), both parsing entry points, earlier parses with a model name prefix and at world scope, and deformable-only, URDF-only, and link-less static models. Backing out each rule separately makes its tests fail. - <drake:child> must not name `world`, just as an SDFormat joint's <child> must not, and a <drake:joint>'s two frames must be on different links. Joining a link to itself used to throw from MultibodyPlant::AddJoint(), with no source location. - Record the __model__ frames that Drake fixes to the world although the model has a canonical link, and reject only those, along with any frame attached to one. A static model with no links can again be named as s::__model__ (and now as s), and an explicit frame on a misplaced model frame no longer resolves silently to the world. - <drake:child> must not be any frame on the world, such as a frame of a static model with no links, not just `world` itself. Such a joint passed the r2 checks and then threw from MultibodyPlant::Finalize(), which can't reverse planar or curvilinear joints, with no source location. libsdformat rejects the same case for a <joint>. - Say "Name a rigid link instead" for a model frame that Drake fixes to the world, since a deformable link has no plant frame to name.
* [feature] TBD [multibody] Implement constraint islands in ICF/CENIC ([#25087][_#25087])  # Partition the cliques of an ICF problem into constraint islands (the connected components of the clique coupling graph) and solve each island as its own smaller convex problem. This is a performance feature: on the hero demo, wall time dropped from 30.2 s to 17.3 s. Islands are enabled by default. Users need to do nothing to get the speedup; IcfSolverParameters::use_islands = false restores the single-problem solve. Caveat: convergence is now judged per island rather than over the whole problem, so results can differ slightly from earlier runs. Disable islands to compare against previous results. From a design idea and vibe-coded prototype by Vince Kurtz. Assisted-By: Claude Opus 4.8 <noreply@anthropic.com>
* [fix] TBD [multibody] Fix SapConstraint::ToDouble() for reduced constraints ([#25146][_#25146])  # - ToDouble() now always returns the Jacobian of the constraint it converts. MakeReduced() replaces only the Jacobian, so the limit, joint friction, PD controller, coupler and tendon constraints rebuilt the Jacobian of the full problem from their stored DOF indices. - With joint locking on AutoDiffXd, this wrote out of bounds, and a joint limit next to a locked DOF had no effect. - DoAccumulateGeneralizedImpulses() of these constraints still uses the stored DOF indices. Only full problems call it.
* [feature] TBD [parsing] Add drake:independent_frames for SDFormat joints ([#25125][_#25125])
* [fix] TBD [geometry,multibody] [geometry] Streamline collision filtering for anchored geometry pairs ([#25150][_#25150])  # Anchored geometry has never been able to collide with other anchored geometry. AssignRole() expressed that by materializing every such pair as an invariant filtered pair -- n(n-1)/2 entries, duplicated in persistent_base_, and copied into every context. Replace them with an anchored set on CollisionFilter and a membership test in CanCollideWith(). Invariant pairs have never been removable via Allow*(), so the predicate blocks exactly what the pairs blocked. We also exclude the possibility of adding a filter on a pair of anchored geometries (the declaration can be made, but no state change is produced). A geometry joins the set when the engine adds it as anchored, so deformable geometry -- on the world frame, but free to move -- is structurally excluded. This also includes a benchmark to facilitate measuring the impact of anchored geometry when creating and evaluating queries on those scenes. In this commit, moving to the anchored-pair predicate reduced the *size* of the collision filter based on the number of anchored geometry. In subsequent branches, it will allow us to see the impact of reclassifying geometries affixed to bodies that are ultimately welded to the world.
* [fix] TBD [geometry] Keep half spaces from breaking fcl tree rebalancing ([#25188][_#25188])  # FCL's rebalancing algorithm dies when a half space is in the tree (the infinite extents confuses it). We can patch around it by allowing the tree to be arbitrarily unbalanced (triggering an alternate, incremental reblancing algorithm instead).
* [fix] TBD [geometry] Fix touching box-box gradients ([#25182][_#25182])  # Fixes two problems: 1. BoxBoxGradient() used to demand that the *inferred* distance between boxes is arbitrarily close to zero. However, that arbitrary threshold could cause problems when the caller would use a value that had a different numerical provenance than the inferred distance -- in some cases, numerical error would cause an erroneous disagreement. - As part of this fix, we eliminate the DRAKE_UNREACHABLE() and allow the code to fall through to a correct gradient, even if the boxes are deeply penetrating. 2. Touching boxes located far from the origin would lead to classification errors due to numerical errors. - We no longer perform the work in the world frame. We do it in box A's frame to erase the impact of both boxes being far from the origin. - We no longer simply trust classifications. When we claim a separating axis we explicitly test it.
* [feature] TBD [parsing] Honor MuJoCo mesh asset refpos and refquat ([#25201][_#25201])  # Parse refpos and refquat on mesh assets and apply the inverse reference pose to mesh geom frames so vertex placement matches MuJoCo. Fixes #22488.
